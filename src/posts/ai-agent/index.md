大家在用 AI 进行 Vibe Coding 时，有没有思考过这样一个问题：我正在用的 AI Agent，真的适合当前的任务或模型吗？

这篇文章将结合我自己的使用经验和实测结果，来回答这个问题。

## 用量消耗

使用 AI 时，大家最关心的无疑是成本，谁也不想白白花冤枉钱。不过，各大平台的计费逻辑主要分为两种：一是 Token 计费，二是请求数计费。那么，哪个 Agent 更费用量，各自又会消耗多少呢？下面我会基于这两种计费逻辑分别比较。

### Token 计费

Token 计费的计算其实有些复杂。例如，DeepSeek 这类缓存命中率高、缓存价格低的模型，与 Astra 这类本身就很贵的模型，需要从不同维度来比较。因此下面分为两种情况，大家可以根据自己使用的模型对号入座。当然，两者也有一些共通之处。

首先说明一下各大 AI Agent 的工具调用逻辑。

PTC 和 STC 的含义如下：

- **PTC**（Programmatic Tool Calling，程序化工具调用）：让模型编写代码来调用工具，一次调用即可完成多件事情。
- **STC**（Sequential Tool Calling，顺序工具调用）：传统的工具调用方式，一次调用只能完成一件事情。

| Codex | DSH | Claude Code | OpenCode |
|-------|-----|-------------|----------|
| PTC | 可手动选择 PTC 或 STC | STC | STC |

#### 缓存命中率高且缓存便宜的模型

每次工具调用结束后，Agent 都会重新请求 LLM，并把此前的全部内容再发送给它。如果模型的缓存命中率高、缓存价格又低，这就不是问题，直接读取缓存即可，基本不怎么烧钱。这种情况下，STC 无疑是最优选择，因为它不需要编写额外的代码。

#### 本身就很贵的模型

对于本身就很贵的模型，情况则不同。使用 PTC 额外编写的代码可能只有十几个 Token，而每多一轮工具调用，就要重新读取前面的一大堆内容，也就是此前推理所用的全部 Token。即使这些内容命中了缓存，相比那十几个 Token，成本依然高得多。因此这种情况下，首选 PTC。

### 请求数计费

请求数计费就简单多了：无论是否命中缓存，消耗的用量都是一样的。既然 PTC 一次工具调用就能完成多件事情，所需的请求数自然更少，所以首选 PTC。

## 速度

速度这件事，实际测一下就知道了，结果是：

**Codex > Claude Code > DSH > OpenCode**

很简单吧，不需要长篇大论。测试方法也很简单：使用同一个模型，完成同一个任务即可。

## 模型能力

模型固然有强弱之分，但好的 Harness 能够缩小这种差距。通常情况下，自家模型搭配自家 Harness 的效果最好。那么，没有自家 Harness 的模型该怎么办呢？我也做了测试，下表列出了各模型对应的最佳搭配。

| Claude | GPT | DS | GLM | Minimax | Gemini |
|--------|-----|----|-----|---------|--------|
| Claude Code | Codex | DSH / Codex | Zcode | Minimax Code | 反重力 |
